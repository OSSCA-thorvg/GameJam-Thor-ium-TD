# 카드 정보·획득 비교 UI

2026-11-08 피드백을 반영해 손패·모집·덱 교체에서 공통 카드 정보를 제공합니다. [배치 사전 판정](placement-preflight.md)의 비용·범위 미리보기와 함께 사용하는 읽기 전용 표시입니다.

## 카드 정보

[CardDetails](../src/game/presentation/CardDetails.h)는 해당 판의 `Catalog`에서 카드 이름·종류·비용·역할 설명·스탯을 구성합니다. 기본 카드 값을 별도 표에 중복 작성하지 않습니다.

- 건물: 사거리·공격력·공격 간격. 포격탑은 폭발 범위, 전격탑은 연쇄 대상 수·연쇄 거리, 화염방사탑은 화염 각도를 추가합니다. 증폭 발전기는 증폭 범위·공격력 증폭·중첩 기준을 표시합니다.
- 유닛: 사거리·공격력·공격 간격·체력·저지 수. 폭파병은 폭발 범위를 추가합니다.
- 마법: 효과 범위와 피해 또는 둔화율·지속 시간. 공격하지 않는 서리·타르 웅덩이에 공격 간격을 표시하지 않습니다.
- 표시값은 기본 성능이며 장비·개별 타워 레벨과 적 방어의 영향은 별도입니다. 상세 창에도 이 기준을 표시합니다.

종류가 변경된 사용자 정의 카탈로그도 실제 `CardCategory`에 따라 표시합니다. 카드별 역할 문구는 현재 규칙이 구현한 효과와 맞춥니다. 피해 계산이나 결제 권한을 UI에 새로 만들지 않습니다.

## 호버·길게 누르기·키보드

[engine/ui](../src/engine/ui/Ui.h)에 게임 종류를 모르는 `inspectable` 기능을 추가했습니다. 현재는 손패·모집 후보·교체 대상 카드가 이 기능을 사용합니다.

| 조작 | 결과 |
| --- | --- |
| 마우스 호버 약 0.3초 | 카드 그림·역할·스탯 표시, 카드를 벗어나면 닫힘 |
| 터치 또는 마우스 길게 누르기 약 0.45초 | 설명을 고정해서 표시하고 손을 떼어도 읽을 수 있음 |
| 고정된 설명이 열린 상태에서 터치 | 설명을 닫으며 같은 터치로 배치·모집·덱 교체를 실행하지 않음 |
| 누른 뒤 먼저 이동 | 기존 드래그 배치. 오래 멈추거나 원점으로 돌아와도 설명 제스처로 바뀌지 않음 |
| Tab으로 카드에 포커스 | 설명 표시. 일반 키보드 선택은 기존 활성화 경계를 사용 |
| 취소·화면 전환·초점 손실·크기 변경 | 검사 중인 제스처와 이전 설명을 폐기 |

길게 눌러 설명을 연 제스처는 놓기·드롭·키보드 활성화로 이어지지 않습니다. 마우스와 터치의 ID가 같아도 캡처를 가로채지 못하도록 `(장치, ID)`를 함께 확인합니다. UI 시간은 게임 속도·일시정지·동작 줄이기 설정과 별도로 흐릅니다.

설명창은 입력 위젯으로 등록하지 않습니다. 호버는 원래 카드를 계속 가리킬 때 유지되고, 고정 터치 설명은 닫는 터치를 소모하므로 뒤의 카드나 버튼이 실수로 실행되지 않습니다. 현재 프레임의 위젯과 가림 상태를 다시 확인해 이전 모달의 설명이 남지 않게 합니다.

## 모집과 새 카드 획득

[CardUi.cpp](../src/game/presentation/CardUi.cpp)에서 모집·획득·교체·설명을 함께 구성합니다. 기존 `GameUi.cpp`에는 모달 껍데기와 분기만 남깁니다.

모집 후보는 카드 그림·비용·기본 스탯을 즉시 보여주며, 호버·길게 누르기로 자세한 역할을 볼 수 있습니다. 후보를 선택하면 교체 화면 위쪽에 **선택한 새 카드의 그림·역할·스탯을 고정**하고 아래쪽에 활성 덱 8장을 표시합니다. 확장 보상도 이름만 보여주지 않고 실제 보상 카드를 같은 형식으로 표시합니다.

기존 카드를 살펴보면 넓은 화면에서는 새 카드 옆에, 작은 화면에서는 새 카드 정보 아래에 비교창을 배치합니다. 새 카드 정보를 가리지 않고 두 성능을 함께 볼 수 있도록 합니다. 기존 카드의 짧은 클릭·탭으로 교체를 확정하는 규칙, 취소·보상 건너뛰기, `Run`이 소유한 실제 후보·가격·결제 시점은 유지합니다.

읽기 전용 진단의 `cardInfo`는 현재 설명의 위젯·데이터·사각형이며, `offeredCard`는 교체 화면에 표시한 새 카드입니다. 상태를 쓰는 웹 API나 별도의 후보·가격 상태는 추가하지 않았습니다.

## 검증

- [규칙·일반 UI 테스트](../tests/native/rules_test.cpp): 마우스 호버, ID가 0인 실제 터치, 길게 누르기 후 놓기·이동·닫기에서 활성화 억제, 드래그 유지, 키보드 포커스, 가림·취소.
- [실제 앱 테스트](../tests/native/application_test.cpp): 사용자 정의 카테고리·비용·스탯, 390px·320px 설명 범위, 모집 후보 검사, 새 카드 고정, 기존 카드 비교 중 무결제, 명시적 교체 후 한 번 결제, 실제 확장 보상, 서리 효과.
- [실제 브라우저 입력](../tests/browser/card-info.js): 손패의 호버·마우스 길게 누르기, 실제 전투·채굴 후 모집·덱 비교, 390px·320px의 실제 터치 시작·유지·끝·닫기와 무소모 확인.

네이티브/WASM 빌드, 네이티브 12개 타깃, 브라우저 11개 시나리오와 Python 문서·의존성 검사 34개가 통과했습니다. 데스크톱과 390px·320px의 실제 브라우저 화면도 확인했습니다.

최초 전체 브라우저 실행의 기존 `playable.js`에서 초기 유닛 배치 대기가 한 차례 타임아웃됐습니다. 동일 빌드의 개별 재실행은 통과했고 나머지 10개 시나리오도 통과했습니다. 해당 실패 원인은 재현되지 않았으며, 이후 조건 대기 실패 시 조건과 전체 공개 상태를 함께 기록하도록 진단을 보강했습니다. Windows 실행·모바일 실기기 성능은 이번 검증에 포함하지 않습니다.
