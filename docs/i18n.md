# 다국어 문자열(i18n)

화면 문장은 코드에 직접 쓰지 않고 언어별 JSON 표에서 키로 찾아 씁니다. 지금은 한국어(`ko`, 원문)와 영어(`en`)가 있습니다. 언어는 메인 화면과 일시정지 창 오른쪽 위의 지구본 버튼, 또는 설정의 언어 탭에서 바꿉니다. 바꾸는 즉시 다른 설정과 함께 저장됩니다.

## 파일과 키

```
content/i18n/ko.json   원문 언어. 모든 키의 기준
content/i18n/en.json   번역. ko.json과 같은 키를 가진다
```

각 파일은 문자열 값만 담은 평평한 JSON 객체입니다. 키는 `화면.영역.항목` 순서로 점을 찍어 짓습니다.

```json
{
  "menu.settings": "설정",
  "home.continue": "제 {id}구역 계속하기",
  "stage.3.name": "동토의 고대 갱도"
}
```

- 문장에 들어갈 값은 `{이름}` 자리표시자로 넣습니다. 언어마다 어순과 조사가 달라서 문장 조각을 이어 붙이지 않습니다. 영어는 같은 키를 `"Continue Zone {id}"`로 씁니다.
- 자리표시자 이름은 모든 언어에서 같아야 합니다. 순서는 달라도 됩니다.
- 줄바꿈·따옴표는 JSON 이스케이프(`\n`, `\"`, `\uXXXX`)를 씁니다. 같은 키가 두 번 나오면 읽기에 실패합니다.

## 코드에서 쓰기

```cpp
#include "game/presentation/Text.h"

g.text(tr("menu.settings"), ...);
button(g, ui, HomeContinue, rect, tr("home.continue", {{"id", std::to_string(stage)}}));
g.text(stageName(meta.id), ...);   // stage.<id>.name
```

`tr`은 고른 언어 → 원문 언어(ko) → 키 자체 순서로 찾습니다. 번역이 빠진 문자열은 한국어로 보이고, 원문에도 없는 키는 키 이름이 그대로 화면에 나와 바로 눈에 띕니다.

| 구성 | 위치 | 역할 |
| --- | --- | --- |
| `StringTable`, `formatText` | [src/engine/text/Strings.h](../src/engine/text/Strings.h) | JSON 표 읽기, 자리표시자 채우기. 게임 내용을 모르는 엔진 코드 |
| `tr`, `setLanguage`, `languages` | [src/game/presentation/Text.h](../src/game/presentation/Text.h) | 지원 언어 목록, 현재 언어, 원문 대체 |
| 언어 저장 | [src/app/Persistence.cpp](../src/app/Persistence.cpp) | 저장 파일·localStorage의 `language` |
| 언어 전환 | [src/app/AppFlow.cpp](../src/app/AppFlow.cpp) | 지구본의 `ToggleLanguage`는 다음 언어, 설정의 `LanguageBase + n`은 n번째 언어를 고른다 |

웹 빌드는 `content/` 전체를 데이터 패키지로 싣기 때문에 JSON을 고친 뒤 다시 빌드하면 반영됩니다.

## 규칙 메시지와 콘텐츠 이름

규칙 계층(`src/game/rules`)은 화면 언어를 모릅니다. 결과 문장은 [`game::Message`](../src/game/model/Message.h)로 키와 값을 돌려주고, 화면·앱 코드가 `tr(message)`로 바꿉니다.

```cpp
return {false, Message("rules.progression.cost", {{"cost", costRef(price)}})};
return {true, Message("rules.mining.arrived", {{"layer", mineLayerRef(next.name)}})};
```

| 값 형식 | 화면에서 바뀌는 결과 |
| --- | --- |
| `@key` | 그 키의 문장(`cardRef(kind)`, `game::ref("ore.iron.name")`) |
| `@key?name=value&name=value` | 값을 채운 그 키의 문장. 값도 같은 규칙으로 바뀐다 |
| `#cost/철/구리/수정/금` | `costText`로 쓴 가격(`costRef(cost)`) |
| 그 밖의 값 | 그대로(숫자 등) |

카드·적·정예·유물·채굴층 이름은 콘텐츠에 언어와 무관한 id로 두고(`gun`, `oreling`, `golem.obsidian`, `surface_shaft`), 화면은 `cardName`, `enemyName`, `eliteName`, `relicName`, `mineLayerName`, `oreName`으로 이름을 찾습니다. id 목록은 [ContentKeys.h](../src/game/content/ContentKeys.h)에 있습니다. 가격 문장은 `costText`가 만듭니다.

## 새 문장 넣기

1. `ko.json`과 `en.json`에 같은 키를 넣습니다.
2. 코드에서 `tr("키")`로 씁니다.
3. 테스트를 돌립니다. 아래 검사가 빠진 키와 자리표시자 차이를 잡습니다.

## 새 언어 넣기

1. `content/i18n/<코드>.json`을 `ko.json`을 복사해 번역합니다.
2. [Text.cpp](../src/game/presentation/Text.cpp)의 `languages()`에 `{"<코드>", "<그 언어로 쓴 이름>"}`을 넣고 배열 크기를 늘립니다.
3. 글꼴이 그 문자를 그릴 수 있는지 확인합니다. 지금 글꼴은 [Noto Sans KR](../content/fonts/NotoSansKR.ttf) 하나이고 한글·라틴 문자를 그립니다. 다른 문자 체계를 넣을 때는 해당 글꼴을 함께 싣습니다.
4. 영어처럼 한국어보다 긴 문장은 버튼·카드 폭을 넘을 수 있으므로 작은 화면(세로 모바일)에서 확인합니다. 바꾼 화면의 `g.text`에는 최대 폭을 주어 넘치면 줄어들게 했습니다.

## 검사

- `thorium-i18n-tests` ([tests/native/i18n_test.cpp](../tests/native/i18n_test.cpp)): JSON 읽기·이스케이프·오류 위치, 자리표시자 채우기, 모든 언어가 원문과 같은 키·같은 자리표시자를 가졌는지, 언어 전환과 원문 대체.
- [tests/test_i18n_keys.py](../tests/test_i18n_keys.py): 소스의 `tr("키")`·`Message("키")`·`ref("키")` 리터럴이 모든 표에 있는지, `src`에 한글 문자열 리터럴이 없는지(언어 선택 버튼의 "한국어"만 예외).
- 실행 중 표에 없는 키를 찾으면 `missingKeys()`에 모이고 진단 상태의 `missingText`로 보입니다. 브라우저 테스트는 시나리오마다 이 목록이 비어 있는지 확인하므로, 코드에서 조합한 키(`"tutorial." + lesson + ".title"` 등)도 실제로 지나간 화면은 검사됩니다.

## 범위

화면에 나오는 문장은 모두 표에서 읽습니다. 메뉴·설정·플레이 방법·크레딧·일시정지, 전투 HUD·검사창·모집·결과 창, 채굴·정비 화면, 카드·적 정보, 튜토리얼, 안내 메시지, 규칙이 돌려주는 결과 문장, 콘텐츠 이름이 포함됩니다. 진단 JSON의 카드 이름·배치 메시지는 언어와 무관하게 id와 키를 씁니다.
