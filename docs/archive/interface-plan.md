# 데스크톱·모바일 UI·UX 계획

작성일: 2026-11-03. Q-07 사용자 답변은 **데스크톱 60 FPS 검증 우선 + 모바일 UI·UX 준비**입니다. 아래 화면·조작은 이 방향을 구체화하는 설계 제안이며 구현 완료나 실제 기기 테스트 결과가 아닙니다. 확정 상태는 [결정 기록](decisions.md), 성능·기기 기록은 [검증 계획](validation-plan.md)을 따릅니다.

## 확정 범위와 제안의 경계

시작·에너지·카드 순환·부대 정비·보상 세부의 추천값은 [첫 3웨이브 플레이 사양](first-playable-spec.md)을 참조합니다. 아래 화면안은 기존 선택과 함께 검토하며 새 추천 규칙의 채택·구현 상태를 의미하지 않습니다.

| 항목 | 상태 | 계획 |
| --- | --- | --- |
| 데스크톱 성능 | 방향 확정 | 60 FPS 목표를 우선 검증, 실제 기준 기기·브라우저·해상도·DPR 미정 |
| 모바일 화면·입력 | 준비 범위 확정 | 작은 화면, 터치 선택·취소, 정비 메뉴와 지상·지하 전환 설계 |
| 모바일 성능 | 기준 미정 | 실제 기기·브라우저·목표 프레임·부하를 별도로 선정하고 측정 |
| 모바일 화면 방향 | 제안 | 가로를 기본 비교안으로 두고 세로는 한 화면·한 작업 중심의 재배치안 준비 |
| 화면에 표현할 게임 규칙 | 확정 | 손패 4장·활성 덱 8장, 제작 광물 철·구리·수정 + 금, 정비당 5굴착 |
| 조작 세부 | 제안 | 카드 탭 선택→대상 탭 사용, 채굴 타일 선택→굴착 버튼, 취소는 무소모 |

모바일 대응은 데스크톱 화면을 같은 비율로 축소하는 대신 전장 영역·손패·정비 메뉴를 다시 배치하는 방식으로 준비합니다. 화면 방향과 조작의 최종 선택은 모형을 확인한 뒤 정합니다.

## 단계별 화면 구성

지상은 탑다운 전투, 지하는 지층 단면 채굴입니다. 전투·정비 단계에 맞춰 전환하며 두 영역을 항상 동시에 그릴 필요는 없습니다. 정비 중 지상 재배치를 열어도 전투는 멈춘 채 정비 단계를 유지합니다.

| 화면 | 항상 확인할 정보 | 주 행동 | 보조 정보·메뉴 |
| --- | --- | --- | --- |
| 지상 전투 | 거점 HP, 웨이브, 전투 에너지, 사용 슬롯/상한, 손패 4장 | 건물·유닛 배치, 마법 사용 | 카드 설명, 선택 대상·사거리, 일시정지 |
| 지하 정비 | 남은 굴착/5·무료 스캔/1, 철·구리·수정·금 잔액, 도구 등급 | 타일 선택·굴착·스캔, 표식 후보 | 제작·모집·슬롯 강화, 지상 정비 전환 |
| 지상 정비 | 생존 유닛 HP, 사용 슬롯/상한, 재료·금 | 선택 치료, 무료 재배치 | 제작·모집, 지하로 복귀 |
| 카드 획득 | 새 후보, 현재 활성 덱 8장 | 후보 1장 선택→기존 1장 교체 | 교체 후 덱, 다음 손패의 최근 획득 우선 안내 |
| 준비 완료 | 다음 공세·위험 예고, 부대 상태 | 다음 전투 시작 | 미완료 작업·제작 조건 안내 후보 |

광물은 아이콘과 이름·개수를 함께 표시하고 금과 전투 에너지는 별도 영역으로 구분합니다. 모집은 금을 써 카드를 얻는 행동이며 전장 슬롯을 즉시 차지하지 않는다는 설명을 붙입니다. 무료 스캔은 정비당 1회로 확정했고 안전한 시작 구역과 남은 굴착 포기 조기 종료를 제공합니다. 스캔은 접근 가능한 경계 1칸의 광물·둥지 유무·숫자 공개이고 굴착·자원 지급과 별개입니다. 현재 이동·굴착 완료 뒤에만 정비를 종료할 수 있습니다. 가격·회복량·안전 구역 크기는 남았습니다.

## 화면 폭별 배치 제안

| 환경 | 전투 배치 | 정비 배치 |
| --- | --- | --- |
| 데스크톱 | 위쪽 상태 HUD, 중앙 전장, 아래 손패 4장, 옆쪽 선택 설명 | 중앙 채굴 보드, 옆쪽 제작·모집·치료 패널 |
| 모바일 가로 | 위쪽 간결한 HUD, 중앙 전장, 아래 손패 4장, 설명은 선택 시 펼침 | 채굴 영역을 유지하고 제작·모집은 한 번에 한 패널로 열기 |
| 모바일 세로 | 위쪽 HUD, 중앙 전장, 아래 손패 4장을 두 줄 또는 축약 카드로 비교 | 한 번에 채굴 보드 또는 정비 패널 하나, 자원 요약·복귀 버튼 유지 |

모바일 가로에서도 브라우저 바와 화면 가장자리 때문에 전장 높이가 줄 수 있으므로 HUD·손패 높이를 먼저 확보한 뒤 전장 크기를 정합니다. 세로에서 네 카드와 코스트가 읽히지 않으면 두 줄 배치를 우선 비교합니다. 전투 손패에 가로 스크롤을 요구하는 안은 우선하지 않습니다.

전장을 읽기 어려울 정도로 줄여야 한다면 시야 이동·확대가 필요한지 모형에서 판단합니다. 그 경우 미니맵·길 끝 위험 예고도 함께 검토하며 처음부터 범용 카메라 기능을 구현하지 않습니다. 채굴 보드는 깊이를 따라 스크롤하되 HUD와 굴착 버튼은 고정하는 후보입니다.

## 마우스·터치 조작 제안

| 행동 | 데스크톱 | 모바일 | 명령을 확정하는 시점 |
| --- | --- | --- | --- |
| 카드 사용 | 드래그 또는 카드 클릭→대상 클릭 | 카드 탭→대상 탭, 대상 누르는 동안 배치 미리보기 | 유효 대상에서 포인터를 놓을 때 한 번 |
| 카드 선택 취소 | Escape 또는 취소 버튼 | 취소 버튼 또는 선택 카드 다시 탭 | 게임 명령 없이 선택 해제 |
| 채굴 | 타일 선택→굴착 버튼, 빠른 조작은 후속 비교 | 타일 선택→광물·경로·등급 확인→굴착 버튼 | 접근 가능한 타일의 굴착 명령 승인 시 |
| 스캔·표식 | 명시적인 모드 버튼과 타일 선택 | 같은 모드 버튼과 타일 탭 | 굴착과 다른 명령으로 구분 |
| 정비 재배치 | 유닛 선택→이동 모드→유효 칸 선택 | 같은 흐름, 선택 유닛과 새 위치 강조 | 새 위치 검증 후 같은 유닛 이동 |
| 선택 치료 | 유닛 또는 부대 목록 선택→치료 | HP가 표시된 목록에서도 선택 가능 | 비용·회복량 미리보기 후 치료 |

드래그를 유일한 사용법으로 두지 않습니다. 손가락에 가려지는 범위·설치 미리보기는 실제 판정 위치를 바꾸지 않고 위쪽 보조 표시로 보여주는 후보입니다. 유효하지 않은 대상에는 이유를 표시하고 카드·에너지·광물·굴착 횟수를 소모하지 않습니다.

빠른 전투 카드 사용에는 매번 별도 확인 창을 띄우지 않는 안을 추천합니다. 제한된 5굴착은 선택과 실행을 나눠 오입력을 줄이고, 광부의 이동·굴착 중 중복 명령은 승인한 대기열 정책에 따라 거절하거나 처리합니다. 대기열 자체는 아직 선택하지 않았습니다.

건물 카드를 선택하면 빈 패드는 설치, 동종 건물은 강화, 다른 종류는 교체로 결과를 구분해 보여주는 안입니다. 행동 이름·소비 에너지·대상 레벨과 교체 손실을 확정 전에 읽을 수 있게 하고 실패 이유를 표시합니다. 손패 교환은 획득 카드 교체와 버튼·설명을 구분하며 비용·순환 순서 확정 뒤 반영합니다.

선택 타워 설명에는 해당 타워 레벨과 광물 공통 장비 효과를 구분해 표시합니다. 개별 레벨 강화와 전체 대상에 적용되는 장비 제작을 혼동하지 않도록 대상 이름·적용 범위를 함께 보여주는 후보입니다.

남은 굴착과 무료 스캔 잔여 횟수는 별도 표시하고 스캔 모드에서는 공개될 정보와 범위를 안내합니다. 스캔 모드는 선택 1칸만 강조하고 공개할 광물·둥지·숫자를 안내합니다. 준비 완료는 현재 이동·굴착 중에는 비활성화해 이유를 표시하고, 작업 완료 뒤 사용자가 누르게 합니다. 남은 굴착이 있어도 종료할 수 있으며 작업 중 종료 요청을 예약하지 않습니다.

숫자 0의 연쇄 공개는 숫자만 보여주고 암반·광물은 그대로 남깁니다. 광부가 이동할 수 있는 열린 갱도와 숫자만 알려진 미굴착 칸을 구분합니다. 실제 둥지 굴착은 다음 웨이브의 추가 적으로 예고하고 스캔·숫자 공개만으로 공세를 늘리지 않습니다. 추가 적 수·출현 구간을 정하면 다음 공세 요약에 표시합니다.

## 제작·모집·덱 교체

새 추천안에서는 첫 화면의 안내·배치 미리보기와 실제 전투 시작을 구분하고, 전투마다 시작 에너지 6을 안내합니다. 건물 대상에 설치·강화·교체와 비용·레벨 손실을 표시하고 손패 교환은 별도 에너지 1 행동으로 제안합니다. 정비 유닛 위치 교환은 두 대상을 강조하며 해산은 이름·현재 HP·슬롯 반환·무환급을 보여주고 확인 뒤 처리하는 안입니다. 실제 게임 화면에 디버그용 ID나 tick을 노출하지 않습니다.

정비는 채굴 뒤 얻은 재료와 금을 바로 제작·모집에 쓸 수 있는 작업 영역으로 구성합니다. 메뉴를 순서대로 한 번씩만 방문하도록 잠그지 않습니다.

모집은 **유닛 카드 후보 3개 → 1개 선택 → 현재 덱 8장 중 교체 대상 선택 → 결과 확인**의 화면 흐름을 제안합니다. 가로에서는 후보 3개를 나란히, 세로에서는 능력·코스트가 읽히는 목록으로 보여줍니다. 제시된 후보와 교체 선택은 메뉴를 닫았다 열어도 같은 모집 상태를 참조하는 안입니다.

금 모집 후보 확인은 무료이며 새 카드와 교체 대상을 선택한 마지막 확인에서 결제합니다. 확인 버튼에 금 비용과 교체 전후 덱을 표시하고 취소는 무소모·후보 유지로 안내합니다. 잔액 부족 시 덱·금·후보를 보존하고 다른 정비를 마친 뒤 같은 후보로 돌아올 수 있는 안입니다. 보유 종류도 포함하되 후보 3종은 서로 다르게 제시합니다. 성공 뒤 재모집·후보 만료·일반 보상 넘김은 Q-20의 남은 결정입니다. 덱 교체로 이미 전장에 있는 생존 유닛의 HP·슬롯을 초기화하지 않습니다.

정비 완료 후 활성 8장으로 손패를 재구성하고 최근 획득 카드 1장을 우선 포함합니다. 유닛 슬롯 상한이 가득 차도 카드 모집 자체는 가능하며, 실제 소환이 불가능한 이유는 전투 카드 쪽에서 안내합니다.

## 작은 화면의 가독성과 입력 경계

버튼·카드·취소 같은 주요 조작 영역은 **44×44 CSS px 이상**을 프로젝트의 시작 목표로 제안합니다. 이는 W3C의 강화 기준을 참고한 설계값이며 모든 맵 타일의 고정 크기나 인증 완료를 뜻하지 않습니다. 작은 대상은 선택 확대·유닛 목록 같은 보조 수단을 비교합니다. [W3C Target Size (Enhanced), Level AAA](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)

설명은 hover에만 숨기지 않고 선택 패널에서도 읽을 수 있게 합니다. 길게 누르기는 필수 행동의 유일한 진입점으로 사용하지 않습니다. 위험·설치 가능 여부는 색과 함께 윤곽·아이콘·짧은 이유를 표시합니다. HTML HUD 버튼은 키보드 포커스와 이름을 제공하는 안이며 캔버스 전장 전체의 키보드 조작 범위는 별도로 검토합니다.

노치·둥근 모서리와 겹치지 않도록 HUD·하단 손패·확인 버튼에 안전 영역 여백을 반영합니다. 사용할 환경 변수는 `safe-area-inset-*`이고 실제 표시 영역 변화 후에도 레이아웃을 확인합니다. [MDN env()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/env)

마우스·펜·터치는 Pointer Events로 받는 후보입니다. 포인터 캡처와 `pointercancel`을 다루고 브라우저 스크롤·확대 정책은 캔버스와 메뉴별로 정합니다. `touch-action`은 해당 영역의 기본 제스처를 제어하므로 페이지 전체의 확대·스크롤을 일괄 차단하지 않는 방향으로 검토합니다. [MDN Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)

게임 입력과 메뉴 스크롤을 구분하고 포인터 취소·화면 회전·뷰 전환·탭 숨김 때 미확정 선택을 정리합니다. 취소가 실제 사용 명령으로 바뀌거나 포인터 이벤트와 후속 클릭 이벤트가 같은 행동을 두 번 발생시키지 않게 테스트합니다.

## 아키텍처에 반영할 범위

웹 UI가 레이아웃·터치 선택 상태를 관리하고 게임 코어에는 같은 타입의 카드 사용·굴착·치료·재배치 명령을 전달합니다. 화면 크기나 입력 장치 때문에 별도 전투 규칙을 만들지 않습니다. 선택 중인 카드와 게임이 소유한 실제 손패는 구분합니다.

CSS 화면 좌표→캔버스 영역→출력 버퍼·뷰 변환→지상 또는 지하 논리 좌표의 단위를 명시합니다. DPR은 필요한 변환에 한 번만 적용하고 화면 방향·패널 크기가 바뀌면 렌더 영역과 입력 변환을 함께 갱신합니다. 자세한 소유권은 [아키텍처](architecture.md)를 따릅니다.

첫 구조는 현재 두 뷰와 HUD에 필요한 입력 어댑터·레이아웃으로 한정합니다. 모바일 대응만을 위해 범용 UI 엔진·장면 계층·기기별 게임 코어를 도입하지 않습니다.

## 검증할 모형과 완료 증거

| 구분 | 설계 검증 크기 후보 | 확인할 내용 |
| --- | --- | --- |
| 데스크톱 | 1280×720, 1920×1080 CSS px | 손패·사거리·설명과 전장, 창 크기 변화 |
| 모바일 세로 | 360×800 CSS px | 카드 4장·코스트·확인/취소, 정비 패널 복귀, 텍스트 줄바꿈 |
| 모바일 가로 | 844×390 CSS px | 낮은 높이, 브라우저 바·안전 영역, 손가락과 미리보기 겹침 |

위 크기는 모형 비교용 뷰포트 후보이며 지원 기기 목록이나 테스트 통과 기록이 아닙니다. 모바일 브라우저 모형·에뮬레이션에서 레이아웃을 확인한 뒤 실제 기기에서 터치 취소·주소창 변화·회전·탭 복귀를 점검합니다. 실제 기기 성능은 별도로 측정합니다.

완료 증거는 화면별 캡처, 카드 사용·굴착·취소·재배치의 입력 기록, 화면 전환 후 동일한 게임 상태, HUD와 전장 판정의 좌표 일치입니다. 아직 화면 모형·실행 코드·기기별 측정은 만들지 않았습니다.
