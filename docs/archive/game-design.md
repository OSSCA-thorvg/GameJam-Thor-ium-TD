# Thor-ium TD 통합 기획안

통합 작성일: 2026-10-31. 개발 전 조사 반영일: 2026-11-03. 기획·게임 사례 조사·기술 검토를 하나로 연결했습니다. **확정 방향**, **검토 방향**, **실험안**을 구분하며 상태는 [결정 기록](decisions.md)을 기준으로 합니다. 추천 규칙과 수치는 제안이며 구현 승인·완료나 성능 실측 결과가 아닙니다.

본격적인 개발 전에는 [시작 계획](preproduction-plan.md)과 [규칙 선택지](rule-options.md)를 먼저 확인합니다. 최신 아키텍처 조사에서 확인한 빈 규칙·선택·책임 경계를 연결했습니다.

## 1. 게임의 정체성

> **깊이 캐고, 끝까지 지켜라.**

**Thor-ium TD는 지하에서 확보한 자원과 발견한 카드로 방어 전략을 발전시키며, 지상의 거점을 지키는 카드 기반 타워 디펜스입니다.**

다수의 적을 처리하는 타격감, 배치와 코스트 운용, 성장한 방어선의 성과를 확인하는 재미가 중심입니다. 채굴은 다음 방어를 위한 투자와 위험 선택을 제공하고, 로그라이트 성장은 매판 다른 조합을 만드는 역할을 합니다.

| 축 | 플레이어의 선택 | 기대하는 재미 |
| --- | --- | --- |
| 전투 | 무엇을 어디에, 언제 배치할까? | 물량 처리와 위기 대응 |
| 채굴 | 어디를 얼마나 깊이 팔까? | 위험 추리와 발견 |
| 제작 | 미래의 채굴과 현재의 방어 중 어디에 투자할까? | 제한된 재료의 배분 |
| 성장 | 어떤 카드를 얻고 어떤 조합으로 바꿀까? | 한 판 안에서 빌드 완성 |
| 맵 확장 | 어떤 공간과 보상을 열까? | 전장과 탐색 목표의 변화 |

## 4. 한 판의 흐름

추천 흐름은 **출발 편성 → 전투 → 해당 구간의 확장·보상 → 정비(채굴·제작·모집·덱 편집·치료·재배치) → 다음 전투 → 최종 공세**입니다. 금을 채굴한 뒤 모집과 덱 편집으로 돌아갈 수 있는 작업 영역으로 제안합니다. 전투·정비 분리는 Q-03=A로 확정했고 보상 순서와 전환 세부는 Q-20·Q-03에서 계속 검토합니다.

~~~mermaid
flowchart TD
    start[출발 덱 편성] --> combat[지상 전투: 카드 배치와 코스트 운용]
    combat --> check{최종 웨이브인가?}
    check -->|아니오| reward[정비 진입: 공세 예고·해당 확장과 보상]
    reward --> mining[정비 작업: 채굴·제작·모집·덱 편집·치료·재배치]
    mining --> prepare[준비 확인·손패 처리]
    prepare --> preview[다음 공세와 추가 위험 확인]
    preview --> combat
    check -->|생존 완료| result[승리와 결과 정산]
    combat -->|거점 파괴| defeat[패배와 결과 정산]
    result --> collection[발견 도감 반영: 저장 규칙 검토]
    defeat --> collection
    collection --> start
~~~

전투에서는 지상과 손패에, 정비에서는 지하와 제작에 집중합니다. 다음 웨이브의 주된 적 구성을 예고하면 채굴·제작에 판단 근거가 생깁니다. 마지막 웨이브를 막으면 심층 탐색을 끝내지 않아도 승리합니다.

## 5. 지상 전투: 건물·유닛·마법

| 카드 행동 | 역할 제안 | 예시 |
| --- | --- | --- |
| 건물 | 경로 옆에 설치해 지속 화력을 제공, 웨이브 사이 유지 | 연사탑·포격탑·전격탑 |
| 유닛 | 경로 위 배치 구역에서 자동 교전, 체력으로 버팀 | 경비병·사수·폭파 드론 |
| 마법 | 즉시 피해·감속·일시 강화로 상황에 대응 | 폭발·서리·과충전 |

유닛은 지정 위치에서 자동 교전·저지합니다. 경비병이 적 2마리를 붙잡고 세 번째부터 통과시키는 예시에서는 포격탑이 모인 적을 처리하고 후방 타워·마법이 새는 적을 상대합니다. 실제 저지 수 2와 적 공격 수치는 아직 실험값입니다.

유닛은 **같은 카드 반복 소환·유닛당 1슬롯·기본 6슬롯**으로 시작하고 진행 중 슬롯 상한을 강화할 수 있습니다. 살아 있는 유닛이 있어도 빈 슬롯과 비용을 충족하면 같은 카드를 다시 사용할 수 있습니다. 금처럼 재화로 쓰는 광물로 강화하며 비용·단계·최종 상한은 미정입니다.

생존 유닛과 남은 HP·점유 슬롯은 다음 웨이브에 유지합니다. 정비 진입이 자동 철수·회복이 되지는 않습니다. 정비에서는 재료를 써 원하는 유닛을 치료하고 무료로 위치를 바꿀 수 있습니다. 재배치는 같은 개체·현재 HP·점유 슬롯을 유지하며 치료 재료·회복량·유효 배치 칸·퇴각은 추가로 정합니다. Q-04=A로 첫 검증의 적 경로·건물 패드·유닛 배치 칸을 고정합니다. 자유 배치·경로 재계산과 지하 중력·사다리는 후속 전환 방향이며 현재 실행 기능에 추가하지 않습니다.

Q-06=A로 건물 카드는 빈 패드 설치·동종 강화·다른 종류 교체에 사용하고 전투 에너지로 손패를 교환합니다. 비용·레벨 상한·배율·교체 손실·교환 순서는 미정입니다. 손패 교환은 덱 순환, 획득 카드 교체는 활성 덱 구성 변경으로 구분하는 안입니다. 개별 타워의 현재 레벨은 설치 개체의 상태이며 같은 종류의 모든 카드가 함께 레벨업하는 규칙이 아닙니다.

## 6. 지하 채굴: 수평 탐색과 수직 성장

지하는 지층을 옆에서 자른 단면입니다. 캐지 않은 암반은 남고, 파낸 영역만 갱도로 비워집니다. 수평은 같은 지층의 탐색, 수직은 더 깊은 광물과 위험으로의 접근입니다. 광부는 선택한 타일까지 열린 갱도를 이동한 뒤 굴착합니다.

지뢰찾기식 규칙은 다음과 같이 제안합니다.

- 숫자는 주변 8칸의 둥지 수, 이동·굴착 연결은 상하좌우 4방향으로 구분합니다.
- 광맥과 둥지는 독립 속성이며, 자원이 보인다고 안전이 보장되지는 않는 안입니다.
- 둥지 개방은 다음 웨이브의 추가 공세로 예고합니다. 한 둥지는 한 번만 위험을 예약합니다.
- 시작 지점에는 안전한 선택을 보장하고 제한된 스캔과 탐색 종료를 제공합니다.
- 숫자 0의 정보 공개와 실제 굴착·광물 획득을 구분합니다.

정비당 5굴착·추리 시간 제한 없음은 사용자 선택으로 확정했습니다. Q-08=A로 최초 둥지 배치의 주변 8칸 수를 유지합니다. 광부는 열린 갱도를 상하좌우로 이동하고 숫자는 대각선을 포함하므로 두 이웃 범위를 구분합니다. Q-09=A로 안전한 시작 구역·정비당 무료 스캔 1회·남은 굴착을 포기한 조기 정비 종료도 선택했습니다. 스캔은 접근 가능한 갱도 경계의 미굴착 1칸에서 광물·둥지 유무·숫자만 공개하며 굴착 횟수·자원을 바꾸지 않습니다. 정비는 현재 이동·굴착 완료 뒤 사용자가 준비 완료를 눌러 종료합니다. 실제 굴착 후 숫자 0은 연결된 0 영역과 경계 숫자만 연쇄 공개하고, 실제 굴착·광물 획득은 별도입니다. 둥지를 실제로 굴착하면 즉시 광부 피해 없이 다음 웨이브 추가 적을 한 번 예약·예고합니다. 안전 구역 크기·추가 적 수는 수치표에서 제안합니다. 실제 보드에서 추측 없이 진행할 수 있는 범위를 검증합니다. 동작 완료·중복 입력으로 작업이나 보상이 두 번 처리되면 안 됩니다.

## 7. 자원·도구·제작의 연결

| 값 | 용도 | 적용 범위 |
| --- | --- | --- |
| 출발 편성점수 | 시작할 카드 조합을 제한 | 출발 시에만 검사하는 제안 |
| 전투 에너지 | 카드 사용·개별 타워 레벨·손패 교환 | 전투 중 회복, 가격·상한 미정 |
| 제작 광물 재고 | 도구·방어 부품·특수 지원 제작과 선택 치료 | 이번 판의 제작·정비 투자 |
| 재화 광물: 금(가칭) | 슬롯 상한 강화·유닛 뽑기 | 제작 재료와 구분하는 이번 판 재화 |

금은 돈처럼 사용하는 광물로 도입합니다. 채굴 시 금 잔액에 바로 더하고 별도 판매 재고를 만들지 않는 안을 추천합니다. 금으로 슬롯과 모집에 투자하고 제작 재료로 장비·도구를 만드는 선택을 구분합니다. 유닛 모집은 금으로 카드 후보 3개 중 1개를 얻고, 실제 소환은 전투 에너지로 하는 Q-23=A를 선택했습니다. 자세한 역할은 [경제안](economy-plan.md)에 있습니다.

첫 검증의 제작 광물은 철·구리·수정 3종, 재화 광물은 금 1종으로 선택했습니다. 토륨은 후속 심층 자원 후보입니다. 수작업 보드 1개에서 정비 두 번의 경로·수량·가격을 먼저 검증하고 자동 생성으로 확장합니다. [첫 보드·경제 초안](first-board-economy.md)에 배치·가격·네 예시 경로의 문서 계산을 마련했습니다. 실제 공개 정보로 진행하는 경험과 전투 균형은 아직 검증하지 않았습니다.

Q-10=A로 에너지는 개별 타워 레벨, 광물은 도구·공통 장비, 룬은 후속 공격 방식 분기로 역할을 정했습니다. 공통 장비는 대상 종류에 속한 기존·신규 개체에 같은 기준으로 적용하는 안이며 개별 타워 레벨과 따로 관리합니다. 룬의 획득 비용·중첩은 후속 결정입니다.

광물을 여러 종류로 나누면 기존 ‘광석 4로 룬, 광석 2로 수리’ 가격은 함께 다시 설계합니다. 이전 가격과 새 제작 비용을 동시에 확정값으로 적용하지 않습니다.

### 도구 등급의 전체판 후보

| 등급 | 제작 재료 후보 | 접근 가능한 대상 |
| --- | --- | --- |
| 기본 드릴 T1 | 시작 장비 | 철·구리·기본 암반, 금 접근도 시작안으로 검토 |
| 강화 드릴 T2 | T1으로 얻는 철·구리 | 수정·단단한 암반 |
| 공명 드릴 T3 | T2로 얻는 철·수정 | 토륨·심층 특수 암반 |

다음 도구의 재료는 현재 등급으로 얻을 수 있어야 합니다. T3만 캘 수 있는 토륨을 T3 제작에 요구하는 순환을 만들지 않습니다. 재료의 위치·수량과 접근 경로도 보장해야 합니다.

작업 횟수제에서는 굴착 애니메이션만 빨라져도 수익은 늘지 않을 수 있습니다. **등급은 새 대상 접근**, **속도는 대기 시간**, **효율은 작업당 수확량·소모량**으로 구분합니다. 첫 검증은 T1→T2와 철 장갑·수정 코일의 두 방어 제작 경로를 비교하는 범위를 권장합니다.

같은 철을 도구에 쓰면 미래 광맥에 접근하고, 경비병 장갑에 쓰면 이번 공세를 오래 버티며, 포탑 부품에 쓰면 처리량을 높일 수 있습니다. 이 배분이 채굴과 타워 디펜스를 연결하는 핵심입니다.

## 8. 카드 획득·시작 덱·부분 계승

플레이 중 카드 획득과 **기존 카드 한 장 교체·활성 덱 8장 유지**를 선택했습니다. 정비 후 손패 4장을 재구성하고 활성 덱의 최근 획득 카드 1장을 우선 포함합니다. 직접 획득 카드와 재료로 만드는 특수 제작법은 콘텐츠별로 구분합니다.

| 발견 경로 | 보상 제안 |
| --- | --- |
| 주요 웨이브 보상 | 카드 또는 성장 후보 |
| 금 모집 | 유닛 카드 3택1·기존 1장 교체·확정 시 결제·취소 무소모·동일 후보 유지 확정, 보유 종류 포함·후보 3종 서로 다름 확정, 종류별 콘텐츠·재모집 미정 |
| 지상 구역 확장 | 구역 특성과 연결된 건물·유닛·마법 카드 |
| 지하 유적·광맥 | 발견 카드·레시피·광물 |
| 제작 | 특수 장비·지원 충전·기존 카드 분기 |

통합전략의 직군별 모집권처럼 확장 전에 보상 종류를 예고할 수 있습니다. 폐병영은 유닛, 공장은 건물, 수정 동굴은 마법 보상을 주는 식입니다. 기본 덱에는 필수 대응 수단을 보장하고 발견 보상은 조합을 발전시키는 역할로 둡니다. 겹친 웨이브·확장 보상은 하나의 지급 순서에서 처리합니다.

### 첫 검증과 후속 출발 편성

첫 검증은 기본 덱 8장·손패 4장으로 시작하고 도감 선택 UI는 후속으로 둡니다. 이후의 기본 4+선택 4·편성점수 규칙은 별도 검토안입니다.

- 후속 도감 편성 후보: 기본 4장과 도감 선택 4장.
- 전체 출발 편성점수 10 이하. 초기 환산은 일반 1·희귀 2·영웅 3.
- 일반 8장도 시작 가능하며 점수를 정확히 10으로 맞출 필요는 없습니다.
- 한 판 도중의 획득에는 출발 점수 제한을 계속 적용하지 않습니다.
- 4~8장 자유 편성은 핵심 카드 순환 속도까지 함께 비교해야 합니다.

희귀도·편성점수·전투 코스트는 별도 값입니다. 통합전략의 희망은 판 도중 모집·승급에도 쓰이므로 우리의 출발 점수와 적용 범위가 다릅니다.

### 판이 끝났을 때

발견 즉시 저장할지, 패배·중도 종료에도 기록할지는 미정입니다. 첫 플레이도 기본 카드만으로 출발할 수 있어야 합니다. 예산 예시는 [카드 시스템](card-system.md)을 참고합니다.

## 9. 로그라이트 성장과 특수 보상

| 성장 축 | 바꾸는 것 |
| --- | --- |
| 카드 획득·교체 | 사용할 행동과 조합 |
| 현장 타워 레벨 | 배치한 타워의 기본 화력 |
| 유닛 슬롯 상한 | 동시에 운용할 수 있는 병력 규모, 기본 6에서 플레이 중 성장 |

| 제작 부품·장비 | 방어 또는 채굴의 투자 방향 |

모든 성장에 별도 화폐·트리를 추가하지 않습니다. ‘저지된 적에게 전격 연쇄’는 기존 룬 후보로 다루고, 카드별 수동 스킬은 조작 부담을 확인한 뒤 검토합니다. 레벨과 룬의 진화 조건은 한 계열부터 시험합니다.

토륨을 사용하는 **핵무기 테마의 일회용 대형 지원 공격**은 검토 방향입니다. 지속 효과의 토륨 발전장치와 긴급 광역 공격 사이에 투자 선택을 둘 수 있습니다. 희소한 제작비·사용 횟수 제한·지정 범위·미출현 적에게는 영향 없음·보스 일부 피해를 후보로 둡니다. 마법 카드와 별도 지원 슬롯 중 방식은 미정입니다.

**심층 코어**는 별개의 선택 탐색 보상입니다. 효과는 아직 정하지 않았으며 토륨 무기나 발전장치와 자동으로 동일시하지 않습니다. 기본 방어 전략으로 최종 웨이브를 통과할 수 있어야 합니다.

## 10. 맵 확장과 화면 구성

| 범위 | 변화 | 상태 |
| --- | --- | --- |
| 지하 갱도 | 채굴로 공개 공간·깊이·자원 접근 증가 | 채굴의 기본 공간 연결 |
| 지상 전장 | 경로와 설치 지점 증가 | 웨이브 뒤 확장 확정, 후보 구성은 검증안 |
| 보상 후보 | 새 카드·레시피 발견 | 플레이 중 획득 방향, 구체 지급은 제안 |

Q-01=A로 지상 확장은 정해진 웨이브 뒤 선택하며 첫 검증은 2웨이브 뒤 1회입니다. 지하 특정 깊이·유적 발견을 필수 해금 조건으로 두지 않습니다. 기존 방어선을 유지하며 바깥쪽 경로를 연장하고 긴 길·적은 설치 지점 대 짧은 길·많은 설치 지점으로 차이를 보여주는 것은 후보 구성 제안입니다.

첫 배치는 고정 경로·건물 패드·유닛 배치 칸으로 시작합니다. 후속 자유 배치·경로 재계산과 지하 중력·사다리 전환을 위한 경계·검증 계획은 [아키텍처](architecture.md)에 정리했습니다. 현재 수직 갱도 이동에는 사다리 제작이 필요하지 않습니다.

그래픽은 캐주얼한 2D입니다. 지층의 윗면·옆면·그림자로 얕은 깊이를 만들고 [컨셉 시안](../concepts/README.md)은 공간 구성 참고로 사용합니다. 지상 탑다운·지하 단면을 단계에 따라 전환하는 구성을 Q-22=A로 선택했습니다. 두 뷰가 같은 판의 자원·진행을 연결합니다.

적 테마는 슬라임·드론·지하 생물·룬 정령 등이 후보입니다. 일반·고속·장갑 역할의 실루엣과 상태 표시를 먼저 정합니다. 풍선은 장르 참고점이며 외형으로 확정하지 않았습니다.

## 11. 기술 구조와 성능 검증

추천 구조는 **C++ 게임 규칙과 ThorVG 렌더링을 하나의 WASM으로 연결하고 TypeScript 웹 셸이 입력·로딩·HUD를 담당하는 방식**입니다. Rubiks의 C++17·Meson·Emscripten 빌드와 수명·테스트 경계를 참고합니다. 버전과 최종 렌더링 백엔드는 미정입니다.

| 책임 | 담당 제안 |
| --- | --- |
| 세션·단계 전환 | GameSession이 RunState를 소유하고 정산·변경 순서 조합 |
| 기능 규칙 | 전투·카드·채굴·성장·월드, 제작 채택 시 재료 재고·레시피 추가 |
| 표현 | 공개 상태·좌표 변환·미리보기·애니메이션 선택 |
| 렌더링 | ThorVG 도형·SVG·Lottie의 장면과 수명 관리 |
| 웹 경계 | 명령·HUD·포인터·오류·탭 수명·도감 저장 어댑터 |

피해·굴착 완료·보상은 게임 시간이 결정합니다. Lottie 재생 콜백이 규칙 결과를 결정하지 않습니다. 실패한 입력은 자원을 소모하지 않고 같은 정산·제작·보상은 한 번만 적용합니다.

WebCanvas도 내부에 WASM을 사용합니다. 커스텀 WASM의 이점은 계산 위치·호출 방식·백엔드를 같은 조건에서 측정해야 판단할 수 있습니다. 경량 라이브러리라는 이유만으로 많은 Lottie 개체의 성능을 보장하지 않습니다. [ThorVG Web](https://github.com/thorvg/thorvg.web), [Emscripten 지침](https://emscripten.org/docs/compiling/best_practices.html)

도형 장면 → 실제 Lottie 적 → 타워·탄환·효과 추가 순으로 부하를 늘립니다. 적 100·300·1,000개는 측정 단계이며 지원 수량이 아닙니다. 게임 계산·애니메이션·그리기·화면 표시 비용, 프레임 시간·메모리·초기 로딩을 기록합니다. CPU와 WebGL을 같은 장면에서 비교하고 최종 환경을 정합니다.

코드·빌드 경계는 [아키텍처](architecture.md), Rubiks 적용 주의점은 [기술 계획](technical-plan.md), 테스트는 [검증 계획](validation-plan.md)에 정리합니다.

## 12. 유저 몬스터 제작과 실험 전장

후속 기능으로 **몬스터 제작 → 샌드박스 소환 → 타워와 카드로 시험 → 파일 공유**를 검토합니다. 체력·이동 속도·거점 피해, 엔진이 지원하는 능력 조합, Lottie 외형을 편집하는 제작실이 후보입니다. 실험 전장에서는 적 수·출현 간격·웨이브·에너지 등을 조절하고 같은 전투 규칙으로 비교합니다.

기본 몬스터도 정의 데이터와 실행 중 상태를 분리해 작성합니다. 새 수치·외형·지원 능력 조합은 데이터로 추가하고, 새로운 행동 유형은 엔진 기능 확장으로 구분합니다. 사용자 스크립트 실행은 별도 장기 검토입니다.

첫 연결판에는 정의 로딩과 규칙 경계를 유지하고 에디터·파일 공유 UI는 후속으로 둡니다. 일반 플레이와 실험 기록을 분리하는 안을 권장합니다. 자세한 범위·도입 순서·검증은 [유저 콘텐츠 확장안](../user-content-plan.md), 상태는 D-29·Q-21에서 확인합니다.

## 13. 첫 검증과 후속 범위

첫 연결판 추천 범위는 **3웨이브, 카드 3분류, 모집용 유닛 3종 후보, 채굴 보드 1개, T1→T2 도구, 방어 제작 2종, 구역 확장과 카드 획득 각 1회**입니다. 철 장갑은 즉시 방어에, T2로 얻는 수정의 코일은 후반 화력에 연결하는 제안입니다. 시작 덱과 순서는 [프로토타입 v0.2 제안](prototype-plan.md)을 따릅니다. 아직 승인된 제작 목록은 아닙니다.

1. 저지 유닛과 범위 공격 타워를 조합하면 배치에 의미가 생기는가?
2. 도구와 방어 장비에 광물을 나눠 쓰는 선택이 다음 전투에 드러나는가?
3. 숫자·스캔으로 위험을 이해하고 채굴을 계속할지 판단할 수 있는가?
4. 확장으로 얻은 카드가 덱 교체와 전투 변화로 이어지는가?
5. 목표 환경에서 Lottie 물량과 카드 입력이 유지되는가?

결과에 따라 룬·진화, T3·토륨·대형 지원 공격, 실제 도감 저장·자유 시작 편성, 전체 8웨이브로 확장합니다. 8~12분은 관찰 목표이며 제한 없는 추리 시간을 포함한 고정 길이 보장이 아닙니다. 배치 방향·빠른 퇴각과 재배치·다수 수동 스킬·자유 미로는 후속 검토 대상으로 둡니다.
