# 검증 계획

아래 항목은 앞으로 구현과 함께 작성·실행할 테스트 계획입니다. 현재 통과한 게임 테스트나 성능 결과를 의미하지 않습니다. 규칙이 미정인 항목은 [결정 문서](decisions.md)에서 먼저 기준을 확정합니다.

2026-11-03 [개발 전 조사](architecture-research.md)를 반영했습니다. [규칙 선택지](rule-options.md)의 답을 받으면 해당 동작을 테스트의 정답으로 고정합니다. [시작 계획](preproduction-plan.md)의 수치·보드 단계도 통과 조건입니다.

## 첫 연결판의 검증 범위

남은 운영 규칙과 전투·배치·공세의 추천 기본값은 [첫 3웨이브 플레이 사양](first-playable-spec.md)의 P-01~P-10을 기준으로 검토합니다. 추천 묶음은 D-59 실험안이며 아래 실제 동작 테스트는 채택한 규칙을 구현할 때 작성·실행합니다. 현재 문서 계산 통과와 구분합니다.

[통합 기획](game-design.md)과 [프로토타입 v0.2](prototype-plan.md)의 현재 제작 후보는 3웨이브, 카드 8종, 모집용 유닛 3종, 보드 1개, T1→T2·방어 제작·금 모집입니다. 첫 검증 기본 덱 8장·손패 4장, 카드 3택1·1대1 교체·정비 손패 재구성·최근 획득 우선은 확정입니다. 철·구리·수정 제작 3종 + 금 재화 1종과 수작업 보드 1개부터 검증하는 방식도 확정했습니다. 실제 배치·경로·가격의 검증은 아직 남았습니다. 종류별 구성·가격은 제안이며 이전 룬·진화 수치는 [v0.1 비교안](archive/prototype-plan-v0.1.md)에 보존합니다.

구체 수치·제안 규칙은 승인 후 테스트의 정답으로 고정합니다. 첫 연결판에는 코어 회수를 요구하지 않습니다. 이후 코어를 추가해도 미회수 승리를 유지하고 보상을 중복 지급하지 않는지 확인합니다. 룬·수리·진화는 새 경제에서 채택한 구매·횟수·중첩·체력 규칙에 따라 검증합니다.

### 공통 규칙의 검증

가능한 규칙은 렌더러 없는 C++ 단위 테스트로 검증하는 안을 우선합니다.

| 성장 | 선행 조건, 중첩·상한, 진화 후 기존 효과의 보존·대체 규칙 |

Q-08=A의 숫자는 최초 둥지 배치의 주변 8칸 수로 고정하며 둥지 개방·제거 후에도 바뀌지 않습니다. Q-04=A의 광부 이동·굴착 접근은 상하좌우 4방향이므로 대각선 둥지는 숫자에 포함되어도 대각선 목표로 바로 이동·굴착할 수 없습니다. Q-09 후속으로 스캔은 접근 가능한 경계의 미굴착 1칸에서 광물·둥지 유무·숫자를 공개하고 굴착 횟수·자원을 바꾸지 않습니다. 실제 굴착 뒤 숫자 0은 연결 영역과 경계 숫자만 연쇄 공개하고 둥지 실제 굴착은 다음 웨이브 추가 적을 한 번 예약·예고합니다. 안전 시작 구역 크기·추리 가능 범위·추가 적 수의 적절성은 검증이 필요합니다. 현재 이동·굴착 완료 뒤 사용자 준비 완료로 정비를 종료합니다.

## 후속 자유 배치·중력·사다리의 검증 경계

Q-04의 답변은 A로 먼저 검증하고 B로 전환할 수 있게 설계하는 것입니다. 첫 구현의 검증은 고정 경로·배치 칸·4방향 이동을 기준으로 합니다. 아래는 B 도입 시 추가할 테스트 계획이며 현재 실행한 테스트나 첫 검증의 완료 조건이 아닙니다.

- 자유 배치의 위치·점유 변경이 모든 필수 진입점과 거점의 연결을 보존하고 실패 시 카드·에너지·점유·경로가 모두 유지됨.
- 이미 이동 중인 적의 ID·위치·HP를 보존하며 새 경로에 연결하고 저지 관계를 다시 검증함.
- HUD와 카드가 고정 패드 인덱스에 묶이지 않고 논리 위치·설치 검사 결과를 사용함.
- 지하의 지지면·사다리 유무에 맞춰 이동·작업 접근을 판단하고, 이동 조건 변경이 굴착 보상·작업 횟수를 중복 적용하지 않음.
- 광부 이동 규칙을 확장해도 최초 둥지 8이웃 숫자와 공개 정보의 의미가 유지됨.

자동 보드 생성은 별도 후속 단계에서 같은 시드의 재현성, 선택한 시작 안전 조건·도구 접근·경로 연결을 검사합니다.

## 웹·아키텍처 경계 테스트

웹 경계와 브라우저에서는 포인터 취소, 카드 드래그 중 리사이즈, 카메라 이동 충돌, 로딩 실패·재시도, 탭 복귀 시 시간 진행, 재시작 후 이전 입력·애니메이션 잔존 여부를 검증합니다.

[코드 구조 제안](architecture.md)을 채택하면 다음 경계도 테스트합니다.

- 게임 규칙 타깃을 ThorVG·브라우저 없이 빌드·실행할 수 있음.
- 잘못된 명령이 카드·자원·보드를 부분 변경하지 않으며 같은 결과를 중복 반영하지 않음.
- 지하 공개 상태에 미공개 둥지·자원이 잘못 포함되지 않음.
- 광부·타워의 규칙상 완료 시점이 Lottie 갱신 빈도나 표현 교체에 영향을 받지 않음.
- 손패 재정렬·타워 교체·판 재시작 후 오래된 ID나 명령이 다른 대상에 적용되지 않음.
- 룬 효과가 기존·신규 타워에 같은 방식으로 반영됨.
- C ABI와 웹 타입의 필드·단위가 일치하고 메모리 증가·재시작 후 버퍼를 올바르게 다시 읽음.

- 뷰 전환이 판을 초기화하지 않고 새 판은 지상·지하·재료·이전 참조를 초기화함.
- SurfacePoint·SurfaceCell·MineCell·ScreenPoint의 변환과 역변환, DPR·카메라·리사이즈 후 입력 일치.
- 명령·공세·이동·저지·피해·사망·도달·정산의 명시한 순서와 동률·동시 승패 처리.
- 같은 적 정의를 공유해도 현재 체력·쿨다운·애니메이션 인스턴스 상태는 독립적임.
- 같은 카드에서 나온 여러 유닛도 각 체력·표적·저지 관계가 독립적이며 이전 소환 개체의 생존만으로 다음 사용이 거절되지 않음.
- 표현 이벤트를 다시 읽어도 규칙 보상이 재발생하지 않음.

손패 재구성에서는 활성 8개 인스턴스가 손패 4·대기열 4에 한 번씩만 들어가는지, 최근 획득 카드가 활성 덱에 있을 때 실제 인스턴스를 우선하는지 확인합니다. 여러 획득·최근 카드 재교체·획득 없음·같은 종류 중복도 적용 기준에 맞춰 검사합니다. 준비 완료 재처리와 UI 재진입이 새 손패·보상을 반복 생성하지 않고 이전 단계 드래그는 거절돼야 합니다.

## 밸런스 실험

[카드 3분류·획득·출발 편성](card-system.md)을 반영하면 시작 장수·필수 카드·편성점수·미발견 카드 사용 조건과 전투 코스트를 분리해 검증합니다. 보상과 교체의 중복 처리 방지, 새 판의 성장 초기화와 선택한 도감 기록 보존, 유닛 사망과 웨이브 사이 생존 HP·슬롯 보존도 필요합니다. 덱 장수 가변안을 비교할 때는 등급뿐 아니라 핵심 카드 순환 속도를 함께 기록합니다.

[광물별 제작·도구 등급](mining-and-crafting-research.md)을 채택하면 제작과 진행 제한을 별도로 검증합니다. 다음 장비 제작에 필요한 재료를 현재 장비로 접근 가능한 위치에서 얻을 수 있어야 하며, 등급 부족·재료 부족 행동은 작업·재료를 소모하지 않아야 합니다. 제작과 지원 공격의 중복 명령에서 재료·충전·효과가 한 번만 적용되는지도 확인합니다. 채굴 장비 투자와 당장 방어할 장비 투자에 따른 승리 가능성을 비교합니다.

같은 맵·시드·공세에서 방어 우선, 채굴 우선, 상황에 따른 절충 전략을 비교합니다. 어느 하나가 항상 최선이 되지 않도록 조정하며 맵과 빌드에 따른 선택의 이유를 기록합니다.

추천 묶음에서는 장갑·재료 치료와 정비 해산 후 에너지 재소환의 비용도 비교합니다. 첫 보드의 치료 4회 경로는 HP가 줄어든 생존 유닛 4명을 가정하므로 실제 병력 상태에서 그대로 실행 가능하다고 간주하지 않습니다. 치료 대상이 적거나 이미 회복했다면 재료를 보존하고 다른 투자와 비교합니다. 긴 길·적은 패드와 짧은 길·많은 패드, 전격탑 획득 후 실제 손패 도착 시점, 에너지 손패 교환 빈도도 함께 기록합니다.

첫 수작업 보드는 정비 두 번의 각 5굴착 안에 도구 재료→상위 광맥→방어 용도가 연결되는지 먼저 계산합니다. 금 광맥과 슬롯·모집 수입·소비가 추가되므로 이전 보드의 검증을 그대로 재사용하지 않습니다. 광물 수량·필수 둥지·치료·교환·보상 선택도 포함합니다. [첫 보드·경제 초안](first-board-economy.md)의 네 예시 경로는 문서 계산에서 도구 등급·상하좌우 접근·정비당 5굴착·지불 가능·재고를 확인했습니다. 실제 플레이 정보·전투·전체 경로의 우열은 미검증이며 예시 경로 계산을 전체 투자 균형의 증명으로 다루지 않습니다.

모바일 UI·UX 검증은 다음 실제 행동으로 확인합니다.

- 카드 탭 선택→대상 탭과 데스크톱 드래그가 같은 카드 사용 결과를 만들고 자원을 한 번만 소비함.

- DPR·브라우저 바·정비 패널 크기 변경 뒤에도 눈에 보이는 타일·사거리와 실제 선택 좌표가 일치함.
- 손패 4장·코스트·거점 HP·슬롯, 철·구리·수정·금과 남은 굴착 수가 읽히고 확인·취소 버튼이 가려지지 않음.
- 메뉴 스크롤이 전장 조작을 발생시키지 않고 캔버스 조작이 중복 클릭으로 처리되지 않음.
- 채굴→금 모집→덱 교체→지상 무료 재배치→지하 복귀가 같은 정비 상태·잔액·HP·슬롯을 유지함.
- 치료 대상이 겹쳐 있어도 목록으로 선택할 수 있고 hover·색·길게 누르기에만 필수 정보와 행동을 의존하지 않음.

아직 위 화면·입력 테스트와 실제 기기 측정은 실행하지 않았습니다.

## 성능 실험

적 100 → 300 → 1,000개는 부하를 늘리기 위한 실험 단계이며 지원을 보장하는 수치가 아닙니다. 도형만 있는 장면, 실제 Lottie 적, 타워·탄환·효과를 추가한 장면을 순서대로 비교합니다.

- 기기·OS·브라우저 버전, 빌드 옵션, ThorVG 버전, 백엔드, 화면 해상도와 DPR을 기록합니다.
- 게임 계산, 애니메이션 갱신, 렌더 준비·그리기, 화면 표시 비용을 가능한 범위에서 분리합니다.
- 프레임 시간의 중앙값·95백분위와 긴 정지, 메모리, 로딩·초기화 시간, 생성·회수 시점을 기록합니다.
- CPU와 WebGL 비교에서는 장면·에셋·해상도를 동일하게 유지합니다.
- 확정한 데스크톱 60 FPS 목표의 프레임 예산은 약 16.7ms입니다. 실제 측정 환경과 부하 장면은 위 표에 기록하며 중앙값·95백분위·긴 정지를 함께 보고 목표 달성 여부를 판단합니다. 고정 시뮬레이션 tick과 렌더 프레임 수는 구분합니다.
- 모바일은 UI·UX 확인 결과와 실제 기기 성능 측정을 분리해 기록합니다. 데스크톱 결과를 모바일 성능으로 대체하지 않습니다.

결과를 얻으면 환경, 재현 방법, 관측값, 채택한 변경, 남은 한계를 함께 문서화합니다. 현재 측정 결과는 없습니다.

## 후속 유저 콘텐츠 검증

[유저 몬스터·샌드박스 확장](user-content-plan.md)을 구현할 때 기본·사용자 정의의 규칙 일치, 필드·버전·능력·에셋 참조 검사, 중복 ID 처리, 실패 뒤 기존 카탈로그 보존을 확인합니다. 분열·반복 생성의 실행 예산, 외형과 판정의 독립성, 일반 플레이와 실험 기록 분리도 검증합니다. 현재 첫 연결판의 완료 기준으로 자동 추가하지 않습니다.

## 현재 문서의 검증

프로젝트 루트에서 `python3 -m unittest discover -s tests -p 'test_*.py' -v`를 실행합니다. 내부 링크·문서 연결, 결정 ID·상태 참조, 규칙 질문의 누락·중복·선택지 형식과 답변·상태 일치, 출발 편성 예산과 연결판 덱 구성을 검사합니다. 첫 보드 수치 검사도 같은 명령으로 실행하며 기호·좌표·초기 안전·도구 등급·예시 경로·굴착 예산·자원 정산을 확인합니다. 문서·수치 검사 통과는 위 게임 테스트나 전투 균형·성능 목표 달성을 의미하지 않습니다.
