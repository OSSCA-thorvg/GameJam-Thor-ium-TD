# 카드 배치 사전 판정

2026-11-06 승인된 배치 사전 판정 API를 구현했습니다. [현재 구조](current-architecture.md)와 [콘텐츠·오퍼·앱 접근 경계](content-offers-boundary.md)에 이어지는 구현 기록입니다.

## 한 규칙으로 조회하고 실행

[Run](../src/game/rules/Run.h)의 `previewPlay(card, target)`는 현재 손패·전투 단계·대상·점유·슬롯·타워 레벨·에너지를 읽어 [PlayPreview](../src/game/model/PlayPreview.h)를 반환합니다. 결과에는 설치·강화·교체·소환·마법의 구분, 실제 비용, 명시적 실패 코드가 들어갑니다. 조회는 에너지·덱·개체 ID·이벤트·난수를 변경하지 않습니다.

~~~mermaid
flowchart LR
    Pointer["선택 / 드래그 + Layout 좌표"] --> Preview["previewPlay · 읽기 전용"]
    Preview --> Plan["private planPlay · 현재 규칙 / 비용"]
    Preview --> Hint["View · 색 / 행동 / 비용 / 사유"]
    Input["카드 놓기"] --> Play["play · 실행 시 재판정"]
    Play --> Plan
    Plan --> Commit["유효할 때 개체 변경 + 결제 + 순환"]
~~~

[Cards.cpp](../src/game/rules/Cards.cpp)의 내부 `planPlay`가 조회와 실행의 유일한 판정 경로입니다. 내부 계획의 손패·타워 인덱스는 호출 안에서만 사용합니다. `play`는 과거의 미리보기 결과를 입력받지 않고 카드 ID·대상으로 현재 상태를 다시 판정합니다. 따라서 조회 뒤 타워를 철거하거나 다른 카드로 강화하거나 유닛이 칸을 차지해도 옛 가격·허용 상태로 실행하지 않습니다. 실패한 실행은 자원·손패·전장을 바꾸지 않습니다.

여러 조건이 동시에 틀리면 유한한 좌표 → 전투 단계 → 손패 포함 → 공간·점유·레벨·슬롯 → 에너지 순서로 이유를 정합니다. 이번 변경으로 잘못된 칸이나 최고 레벨 타워는 에너지 부족보다 먼저 설명합니다. 정상 설치·강화·교체·소환·마법의 가격과 효과는 유지합니다.

`playAvailability(card)`는 현재 배치 후보를 같은 판정으로 조회하여 사용 가능한 대상의 유무, 최소·최대 비용, 현재 지불 가능 여부를 요약합니다. UI에 별도 가격 공식이나 타워 탐색 규칙을 두지 않습니다. 현재 소수의 고정 패드·유닛 칸을 순회하며 후보 벡터를 새로 만들지 않습니다. 자유 배치·다수 대상 규칙을 도입할 때는 이 후보 순회 부분을 함께 확장합니다.

## 화면 피드백

2026-11-08 피드백을 반영하여 현재 에너지·회복 게이지·소모 피드백을 손패 바로 아래로 옮겼습니다. 상단에는 거점·부대·광물 정보를 두며, 320px에서는 카드 내부 배치를 조정해 하단 에너지 바와 함께 표시합니다. 대상별 카드 비용과 현재 에너지를 같은 영역에서 비교할 수 있습니다.

드래그·터치 이동 중에도 실제 배치 위치를 중심으로 공격·효과 범위를 표시합니다. 건물·유닛·마법 모두 해당 판의 `Catalog` 범위를 사용하고, 같은 범위 그리기를 설치 후 대상 선택과 공유합니다. 미리보기 범위는 전장에 잘라 그리며 설치 가능 여부에 따라 초록·빨강으로 표시합니다. 마법의 소수 좌표와 카드 교체 대상의 실제 종류를 유지합니다. 놓기 전에는 개체·에너지·손패를 변경하지 않습니다.

이번 UI 후속 검증에서는 네이티브 12개 타깃과 브라우저 10개 시나리오가 통과했습니다. 실제 픽셀로 에너지 소모와 범위 원을 확인하고, 실제 터치 드래그와 320px의 손패·에너지 바 인접 배치를 검증했습니다.

[Placement.cpp](../src/game/presentation/Placement.cpp)는 `Layout`으로 커서 위치를 논리 좌표로 바꾼 뒤 판정합니다. 건물·유닛은 실제 입력과 같이 칸에 맞추고 마법은 소수 좌표를 유지합니다. [PlacementPreview](../src/game/presentation/PlacementPreview.h)는 한 번 그릴 때만 쓰는 표시 문맥입니다.

- 유효한 패드·유닛 칸과 현재 대상은 초록색, 사용할 수 없는 곳은 빨간색입니다. 현재 대상의 표시 원은 가운데를 비워 타워·유닛·드래그 그림을 가리지 않습니다.
- 대상 근처에 `강화 · 에너지 2`처럼 실제 행동과 비용을 표시합니다. 불가능하면 이유를 한 줄 더 표시합니다. 색과 문구를 함께 사용합니다.
- 대상이 정해지기 전 손패는 가능한 최소 비용과 가변 가격의 `+`를 보여줍니다. 에너지가 2이고 설치가 3이어도 강화 2가 가능하면 사용 가능한 카드로 표시합니다.
- 대상을 가리키면 해당 카드 배지와 선택 정보도 그 대상의 실제 비용을 보여줍니다. 사용할 수 없는 카드를 선택해서 이유를 확인하거나 손패를 교환할 수 있습니다.
- 카드를 끌어다 놓는 것은 한 번의 시도입니다. 놓기가 거절되면 카드는 흔들림과 거절 메시지를 남기고 선택이 풀리며, 입구 표시와 미니맵이 바로 돌아옵니다. 카드를 눌러 선택한 뒤 전장을 누르는 방식은 거절되어도 선택을 유지해 다른 대상을 고르거나 교환할 수 있습니다.
- 작은 화면에서도 안내창을 전장 안에 제한합니다. 일시 정지·설정 등 다른 화면·대화상자·필수 보상 중에는 안내를 숨깁니다. 이런 앱 입력 제한은 게임 규칙과 별도로 유지합니다.

읽기 전용 `debugState()`의 `placement`는 범위를 포함한 마지막으로 그린 대상 또는 `null`입니다. `energyBar`는 현재 하단 에너지 표시의 기하이며, `handAvailability`는 현재 손패의 요약입니다. 진단은 상태를 쓰는 웹 API를 추가하지 않으며, 실행 권한이나 영속 스냅샷으로 사용하지 않습니다.

## 검증

- [규칙 회귀 테스트](../tests/native/play_preview_test.cpp): 모든 행동·가격, 잘못된 위치·카드·단계, 점유·슬롯·최고 레벨·에너지 부족, 저렴한 강화의 사용 가능성, 반복 조회의 무변경, 조회 이후 상태 변경에 대한 재판정과 단일 커밋.
- [컨트롤러 테스트](../tests/native/controllers_test.cpp): 에너지가 부족한 놓기의 무변경·메시지·선택 해제, 눌러 선택한 카드의 거절 뒤 선택 유지.
- [실제 앱·픽셀 테스트](../tests/native/application_test.cpp): 손패의 사용 가능 색, 대상의 초록/빨강 픽셀, 실제 강화 가격, 거절 시 무변경, 일시 정지·설정에서 숨김, 320×568 크기 변경.
- [실제 브라우저 입력](../tests/browser/placement.js): 드래그 중 유효/무효 대상 전환, 놓을 때 한 번 실행, 에너지 2에서 강화/설치의 다른 판정, 메뉴·정지·작은 화면 표시.

네이티브/WASM 빌드, 네이티브 12개 타깃, 브라우저 9개 시나리오와 Python 문서·의존성 검사 34개가 통과했습니다. 기존 공유 프레임 브라우저 테스트는 크기 변경 후 앱이 새 크기로 그린 것을 기다린 뒤 다음 컨트롤을 조작하도록 보강했습니다. 브라우저 실행기는 `npm run test:browser -- placement.js`처럼 등록된 시나리오를 개별 실행할 수도 있습니다.

이번 작업에서 렌더링 계층 최적화나 설정 저장소는 변경하지 않았습니다. Windows 실행·모바일 실기기 성능을 이번 검증에 포함하지 않습니다.
