# 첫 구현 v0.1

구현일: 2026-11-04, Asia/Seoul. 사용자의 ‘일단 한번 구현해봐. 구현본 보고 수정해나가자’ 요청에 따라 SDL3·ThorVG·공통 C++ UI로 첫 3웨이브 시연판을 만들었습니다. 이전의 기획·수치 초안은 실험 기준으로 사용하며 밸런스 확정과 구분합니다.

## 실행

프로젝트 루트에서 실행합니다. Python 3.12 이상, C++17 컴파일러, Meson, Ninja, pkg-config가 필요합니다. CMake·fontTools는 프로젝트의 `.tools/venv/`에 설치하고, SDL·ThorVG 소스와 빌드는 `.deps/`·`subprojects/`·`build/`에 둡니다. 전역 패키지 설치는 하지 않습니다. 최초 실행에는 의존성 다운로드가 필요합니다.

~~~sh
python3 tools/build.py native
./build/native/thorium
~~~

웹 빌드는 Emscripten SDK가 추가로 필요합니다. `EMSDK` 환경변수를 지정하거나 현재 워크스페이스의 `ThorVG/playground/emsdk`를 자동으로 찾습니다. 이 환경에서 검증한 SDK는 6.0.0입니다.

~~~sh
python3 tools/build.py web
python3 -m http.server 8317 --bind 127.0.0.1 --directory dist
~~~

[로컬 시연판](http://127.0.0.1:8317/)을 엽니다. 네이티브와 웹 모두 게임·HUD·손패·팝업을 같은 C++ 코드로 그리고 조작합니다. HTML은 캔버스·로딩·오류 표시만 담당합니다. Windows용 소스 경계는 준비했지만 Windows 빌드·실행은 아직 검증하지 않았습니다. 네이티브 실행 파일은 현재 개발 폴더의 콘텐츠 경로를 사용하며 설치 패키지는 후속입니다.

## 해볼 수 있는 것

1. 메인에서 새 원정을 열고 첫 웨이브를 시작합니다. 이후 연사탑은 둥근 패드, 경비병은 길 위 작은 칸에 놓습니다. 카드 탭→대상 탭과 드래그 배치를 모두 지원합니다.
2. 3웨이브 동안 건물 설치·동종 강화·타종 교체, 반복 유닛 소환·자동 저지, 마법·손패 교환을 사용합니다. 에너지는 2.5 게임 초마다 1 회복하고 ×2 속도로 확인할 수 있습니다.
3. 전투가 끝나면 지하에서 타일을 선택해 광부를 자동 이동·굴착시킵니다. 정비당 5굴착·무료 스캔 1회, 숫자 정보만의 0 연쇄 공개, 둥지의 다음 웨이브 추가 공세를 연결했습니다.
4. 철·구리로 T2 도구, 철로 장갑, 금으로 슬롯과 유닛 카드 모집, 철·수정으로 전격 코일을 만듭니다. 유닛 카드는 3택1 뒤 기존 카드와 교체할 때 금을 냅니다.
5. 전투·정비 중 배치한 건물·유닛을 눌러 사거리·상태를 확인하고 철거·철수합니다. 정비 중 유닛은 별도 ‘위치 이동’을 누른 뒤 무료 이동·점유 칸 교환을 하거나 재료로 치료합니다. 이동은 HP·ID·슬롯을 유지합니다.
6. 2웨이브 뒤 긴 경로/추가 패드의 확장을 선택하고 전격탑 보상을 덱에 넣거나 건너뜁니다. 마지막 웨이브 생존은 승리, 거점 HP 0은 패배입니다.

초기 손패의 연사탑 + 경비병은 에너지 6으로 바로 배치할 수 있습니다. 첫 정비의 도구 경로 예시는 B1 → C1 → B2 → C2에서 철4·구리4 확보 → T2 제작 → D2에서 금4 획득입니다. 좌표는 보드 왼쪽부터 A~E, 위부터 깊이 0~5입니다.

## 첫 피드백 반영: 철수와 화면 테마

2026-11-04 ‘배치한 대상 철수’와 ‘게임 같은 UI’ 요청을 반영했습니다. 금속 프레임·구리 테두리·광물 토큰·분할 게이지로 채굴 기지의 계기판을 구성하고, 건물·유닛·마법의 색과 벡터 일러스트를 손패·선택창·모집창에서 공유합니다. 전장에는 설치 기반·식생·선택 링을, 지하에는 암석의 단차·광맥·접근 가능한 경계 표시를 추가했습니다. 게임 UI는 계속 ThorVG로 그립니다.

철수는 전투·정비 중 가능하고 확인 창을 거칩니다. 확인 중에는 전투·굴착 시간이 멈추며 취소하면 배치를 유지합니다. 건물은 강화 레벨까지 제거되고, 유닛은 슬롯을 반환하며 저지하던 적을 즉시 해제합니다. **환급 없음**은 이번 구현의 실험 규칙입니다. 에너지·광물·금과 카드 덱·손패 순환은 철수로 바뀌지 않고, 다시 배치하려면 카드를 새로 사용합니다. 환급 비율의 최종 밸런스는 후속 피드백 대상입니다.

## 카드 순환과 전투 피드백

2026-11-04 후속 피드백으로 손패의 즉시 교체를 퇴장 → 등장 → 강조의 전환으로 바꿨습니다. 종류가 같은 카드도 인스턴스 ID가 달라지면 재생합니다. 0.16초 퇴장 후 0.38초까지 새 카드가 들어오고, 0.85초까지 테두리와 DRAW 표시를 유지합니다. 이동 중인 카드는 클릭·드래그·숫자 키로 사용하지 못하며, 비활성 상태에서 누른 포인터를 나중에 떼어도 새 동작으로 실행하지 않습니다. 다음 카드의 이름·비용도 덱 상단에 표시합니다.

카드 사용과 에너지 1 교환 모두 같은 전환을 사용합니다. 정비 후에는 현재 손패를 다시 나눠 주며 모집·확장 보상으로 얻은 카드의 등장도 보입니다. 잘못된 배치는 붉은 테두리·흔들림·오류 문구로 알리고 성공 전환이나 비용을 만들지 않습니다. 에너지 사용량은 HUD에 짧게 표시합니다.

전투에는 발사 반동·섬광·사격선, 피격 순간의 눌림·빛·피해 숫자, 범위 공격의 충격파, 처치 파편, 거점 피해의 붉은 경계 표시를 추가했습니다. 같은 화면 갱신에서 한 대상이 받은 피해 숫자는 합쳐 표시합니다. 전투 결과가 먼저 확정된 뒤 연출하며, 이펙트 종료가 피해·처치·웨이브 진행을 결정하지 않습니다. 후속 요청으로 [사운드 시스템](audio-system.md)을 추가했습니다. 전역 히트스톱은 아직 적용하지 않았습니다.

규칙은 [Types.h](../src/game/model/Types.h)의 `CombatEvent`로 확정 사실만 내보내고, [Feedback.h](../src/game/presentation/Feedback.h)·[Feedback.cpp](../src/game/presentation/Feedback.cpp)가 손패 스냅샷과 연출 시간을 소유합니다. 이벤트는 한 번 소비하며 미소비 대기는 256개, 동시 연출은 128개로 제한합니다. 일시정지·확인 창에서는 전투 연출도 정지하고 손패 전환은 실제 시간으로 완료됩니다. 저장·전투 상태에 연출 시간을 넣지 않았습니다.

## Lottie 개체 상태

[Lottie·개체 애니메이션](animation-system.md)을 추가했습니다. 적은 독립 플레이어로 대기·이동·공격·사망을 전환합니다. 공격·사망은 원본 마커 구간을 한 번 재생하며, 처치된 적은 게임에서 즉시 제거하고 시각용 사망 연출만 유지합니다. 게임의 배속·일시정지·메뉴 정지를 따르고 새 원정에서 개체 재생을 초기화합니다.

폴더마다 빈 매니저나 라이브러리를 만들지 않았습니다. 현재 범용 UI 기반은 히트 테스트·캡처·포커스부터 시작하며, 자동 레이아웃·스크롤·텍스트 편집기·접근성 트리는 아직 만들지 않았습니다. 버튼의 게임별 외형과 화면 배치는 게임 표현에 둡니다. 에셋과 시간의 별도 서비스 추출은 실제 공유 요구가 생길 때 진행합니다.

ThorVG 소프트웨어 출력 → SDL 스트리밍 텍스처 경로를 사용합니다. 물리 픽셀 밀도는 최대 1.5와 약 220만 픽셀로 제한했고, 논리 입력 좌표와 구분했습니다. GPU 백엔드·대규모 적 부하·60 FPS 기준 기기의 성능 측정은 후속입니다. 규칙 결과는 Lottie나 UI 애니메이션 완료에 의존하지 않습니다.

## 검증

~~~sh
python3 -m unittest discover -s tests -p 'test_*.py' -q
meson test -C build/native --print-errorlogs
~~~

네이티브 빌드 명령은 빌드 후 Meson 테스트도 실행합니다. `rules-and-input`은 SDL·ThorVG를 링크하지 않고 카드 순환·반복 소환·슬롯·유닛 유지·치료·굴착·스캔·둥지·모집·확장·자연스러운 3웨이브 승패·포인터 취소를 확인합니다. `native-render-smoke`는 SDL dummy/software 드라이버에서 실제 한글·Lottie·화면을 그려 BMP로 저장합니다.

2026-11-04 결과는 문서 검사 29개 통과, 규칙·입력 168항목 통과, 오디오 51항목 통과, SDL dummy 렌더링·오디오 출력 통과입니다. macOS 실제 디스플레이 드라이버에서도 `--smoke-test`로 숨김 창의 4프레임 렌더링과 정상 종료를 별도로 확인했습니다. 일반 터미널의 Playwright 실행과 연결된 브라우저 도구 양쪽에서 아래 실제 입력 시나리오가 통과했습니다. 화면 프로세스 생성이 제한된 터미널 환경에서는 브라우저·디스플레이 권한이 있는 실행 환경이 필요합니다.

초기 화면·설정·원정 계속하기는 [메인·설정 흐름](front-end.md)에 정리했습니다.

효과음 파일명·합성음 대체·음량 설정과 테스트는 [사운드 시스템](audio-system.md)에 정리했습니다.

실제 브라우저 입력 시나리오는 [playable.js](../tests/browser/playable.js), [withdrawal.js](../tests/browser/withdrawal.js), [feedback.js](../tests/browser/feedback.js)에 있습니다. 철수의 확인·취소·전투 정지·비용과 손패 유지, 정비 이동, 모바일 재탭 취소·철수도 확인합니다. 1200×900·980×739·390×844·320×568에서 활성 입력 영역의 화면 경계와 겹침을 검사합니다. 같은 종류 카드의 ID 교체·입력 잠금·수동 교환·실패 표시·실제 피격·일시정지 중 연출 시간도 검사합니다. WASM의 읽기 전용 공개 상태·UI 좌표만 사용하며 게임 상태를 직접 바꾸는 테스트 export는 없습니다. 서버가 실행 중인 상태에서 선택적으로 다음 명령을 사용합니다.

~~~sh
npm ci
npx playwright install chromium
npm run test:browser
~~~

확인한 범위는 데스크톱 Chromium의 클릭·드래그·전투→정비·채굴·제작·모집·재시작과, 390×844 터치 에뮬레이션의 탭·중복 결제 방지·touchCancel입니다. 실제 휴대전화·Windows 실행·모든 브라우저 호환성·화면낭독기·밸런스와 성능 기준의 완료를 뜻하지 않습니다.
